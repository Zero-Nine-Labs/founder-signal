# LinkedIn post creator

Create one useful post package for any founder, from initial angles to content and caption. Keep the founder's facts, audience, goal and voice separate from other founders. Do not require a weekly plan or profile audit first.

## Set the scope

Reuse the founder brief, source material and any selected calendar brief. Establish the audience, reader outcome and the one section to cover. A section can mean a source-document passage, a topic or pillar, or a funnel stage. Keep topic and stage distinct, and honour both when supplied. Reuse a section explicitly selected earlier in the current conversation or in the selected brief; do not ask the user to repeat that choice.

If no specific section has been selected, or the selection is ambiguous, ask a concise clarification question and wait for the answer before generating ideas, running CPIO or drafting content and captions. A company name, business goal or unselected source document does not select a section. Do not silently choose a default or cover every section. Offer the actual available section names when known; otherwise ask, "Which section should this post focus on? You can name a topic, content pillar, funnel stage or source-document section." Choose a section yourself only when the user explicitly asks you to choose, and state the choice before proceeding.

Keep all ideas and copy within that selection. Surrounding context is useful only when needed for accuracy. Do not broaden into the whole guide, other pillars, a funnel mix or a weekly calendar.

Ask only for essential missing inputs. Use supplied facts, approved founder views and inspected sources. If a case study or personal story lacks proof, request the missing facts or use a supported explanatory angle. Never invent results, customer quotations, recurring buyer questions or founder experience. Keep private details out of public copy unless publication is permitted.

## Find an angle

Offer a small set of distinct ideas within the selected section, unless the user already chose an idea or requested a different number. For each, give the reader's question, one useful takeaway and the source or founder input that supports it. Label proposed questions as hypotheses rather than observed customer demand.

Choose the strongest supported angle and briefly explain why. Proceed to a draft without requiring routine idea approval. If the user asks only for ideas, stop after the ideas. A user-selected angle takes priority.

## Create with CPIO

Read [writing.md](references/writing.md) before creating the content. Apply Convey, Package, Information and Order in sequence:

1. **Convey:** decide the one point the reader should understand, and why it matters to this audience.
2. **Package:** choose an angle, hook and format that help deliver that point. Honour a requested format.
3. **Information:** select supported facts, examples and explanations. Exclude information outside the section and identify essential gaps.
4. **Order:** arrange the content for a cold reader, with context before dependent details and evidence beside the relevant claim.

Show a short CPIO summary for the chosen angle, unless the user wants only final copy. Do not turn the four steps into separate approval gates. CPIO improves the writing process; it does not guarantee reach or sales.

Match the deliverables to the package:

| Format | Content | Caption |
|---|---|---|
| Text post | Complete post copy | The post copy itself. Do not duplicate it as a second caption. |
| Carousel | Slide-by-slide copy with useful explanations, examples or steps | A companion caption that introduces the value and adds relevant context, without repeating every slide |
| Video | Speakable script, with visual or demonstration cues where useful | A companion caption that introduces the topic and takeaway |
| Single image or screenshot | Exact on-image wording and a clear visual brief | A caption that supplies the explanation or context the image needs |

Content must deliver the promised answer, not just list slide titles or suggest a format. Captions and assets must support the same point. Include a CTA only when it serves the brief, with a supported contact route. Do not force a sales pitch or engagement bait.

Copy, scripts and visual briefs are drafts, not rendered assets. If the user requests a finished visual or file, use appropriate available tools and verify the artifact. If that cannot be completed, state what remains. Never claim a suggested or unrendered asset exists.

## Edit and deliver

Read [human-voice.md](references/human-voice.md) for every draft and revision. Apply the supplied writing rules to the content and caption: scan, rewrite preserving meaning, build voice from real founder language, then self-audit. Recheck scope, hook payoff, facts and caveats with the editing checks in writing.md. Default to plain Australian English when no other language or voice is supplied.

Return the ideas, selected angle with its concise CPIO summary, content and caption. Adapt that structure to a narrower user request rather than forcing every field. Keep source notes and material gaps outside the public copy. Identify copy ready for founder review separately from assets still needing design, recording or permission. Unresolved factual placeholders are not ready to use.

Return work in chat unless an artifact is requested. Creation does not publish, schedule or edit LinkedIn. For a weekly calendar, use a content-planning workflow; for a supplied draft or already-defined writing brief, the post-writer workflow remains suitable. This skill stands alone and does not require those skills to be installed.
